# WeeklyReview#202643

Black October: the day people discovered Internet is a dangerous place this week. And what a week... It was absurdly hard days for the security world, and it's probably not done yet (because this note has been updated a lot). A huge amount of security issues and other crazy discoveries were announced in few hours/days. Good luck to all my sysadmin friends working to make their infrastructure safer.

One of the very first big issue was due to a certificate authority problem. Many certificates generated by eMudhra (an Indian company) were totally unsafe. Indeed, their private keys were all an unique integer between 0 and 255 (uint8), instead of a long integer encoded on 384 bits. All started on 17th October, when "Wayne" (a security guy playing with new tools), discovered 8 odd certificates. A ticket was opened on [Mozilla's Bugzilla](https://bugzilla.mozilla.org/show_bug.cgi?id=2083449). The thread is still very active. The consequences are concerning. [Python](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576) is impacted and many packages must be updated. The [Erlang Ecosystem Foundation](https://com.erlef.org/wg/sec/2026/10/20/root-certs-compromised.html) did also a post about this issue explaining which modules must be upgraded as soon as possible. All [Operating Systems](https://emudhra.we-have-a-problem.com/) are also impacted by this issue, and the certificates must be upgraded locally as well. The [`mitmproxy` project](https://github.com/mitmproxy/mitmproxy/issues/8497) already includes on its last version those certificates. More information below.

- [**eMudhra emSign PKI Services: CP/CPS documents not updated for current requirements**](https://bugzilla.mozilla.org/show_bug.cgi?id=2082872) from Mozilla's Bugzilla thread;
- [**eMudhra: Private key compromise of Intermediate Certificates**](https://bugzilla.mozilla.org/show_bug.cgi?id=2083449) from Mozilla's Bugzilla thread;
- [**Information for Python users regarding eMudhra / emSign CA certificate security incident**](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576) from Python's Discuss thread;
- [**eMudhra CA Intermediate Certificates have been compromised, CA updates needed on all TLS components**](https://com.erlef.org/wg/sec/2026/10/20/root-certs-compromised.html) from the Erlang Ecosystem Foundation;

While writing my article on the `libsodium` library port on Dart using FFI, I also checked the Erlang driver called [`erlang-libsodium`](https://github.com/potatosalad/erlang-libsodium). Sadly this package was kinda old ([version 1.0.18+](https://github.com/jedisct1/libsodium/releases#release-1.0.18-RELEASE) released in 2019). Few issues and PRs have been opened to fix the library, but the project seems to be dead. Anyway, I wanted to use is to test the interoperability with the Dart implementation, and decided to fork it. `libsodium` has been updated to version 1.0.22 (the latest), the PRs have been merged, and I'm working on doing a lot of test cleanup.
