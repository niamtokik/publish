# File System Management in Dart

It's a good time to also investigate a bit the dart I/O interfaces, especially the one related to files. The `dart:io` package must be imported to deal with files and directories in Dart.

```dart
import 'dart:io';
```

A file in Dart is an object instantiated by the [`File` class](https://api.dart.dev/dart-io/File-class.html). This object can be created by simply invoking the [default constructor](https://api.dart.dev/dart-io/File/File.html), where its argument will be a `String`.

```dart
// default constructor can be used
// to create a new object pointing to
// a local file.
File myFile = File("./file1.test");
```

[`fromRawPath()`](https://api.dart.dev/dart-io/File/File.fromRawPath.html) is another constructor, it opens a file based on an `List<Uint8>` (`Uint8List`), this kind of data is usually generated by [`utf8.encode`](https://api.dart.dev/dart-convert/utf8-constant.html) or [`ascii.encode`](https://api.dart.dev/dart-convert/ascii-constant.html).

```dart
// fromRawPath constructor can be used
// to open a file based on a raw path,
// an Uint8list.
File myFile2 = File.fromRawPath(
  ascii.encode("./file2.test");
);
```

Finally, the [`fromUri()`](https://api.dart.dev/dart-io/File/File.fromUri.html) constructor will open a file based on an [`Uri`](https://api.dart.dev/dart-core/Uri/Uri.file.html) object.

```dart
// fromUri is another construct that
// can be used to open a file based on
// an Uri.
File myFile3 = File.fromUri(
  Uri.file("./file3.test")
);
```

Now the file object has been created, many attributes and methods are available to control it. Let check first the attributes. In the previous examples, all objects are using a relative path, when the object is returned, the `absolute` path attribute is set. It is the `absolute` path representation of the data previously passed.

```dart
print(myFile1.absolute);
print(myFile2.absolute);
print(myFile3.absolute);
```

```console
$ dart run
File: '/home/user/tmp/cboring/./file1.test'
File: '/home/user/tmp/cboring/./file2.test'
File: '/home/user/tmp/cboring/file3.test'
```

The original path passed as first argument can be retrieved with the [`path` attribute](https://api.dart.dev/dart-io/File/path.html).

```dart
print(myFile1.path);
print(myFile2.path);
print(myFile3.path);
```

```console
$ dart run
./file1.test
./file2.test
file3.test
```

The file object can also returns an Uri object with the help of the [`uri` attribute](https://api.dart.dev/dart-io/FileSystemEntity/uri.html).

```dart
// this is a closure helper to show
// the properties from an Uri object and
// return them as a Map.
final toMap = (Uri uri) {
  return {
    "scheme": uri.scheme,
    "host": uri.host,
    "path": uri.path,
    "fragment": uri.fragment,
  };
 };

print(toMap(myFile1.uri));
print(toMap(myFile2.uri));
print(toMap(myFile3.uri));
```

```console
$ dart run
{scheme: , host: , path: file1.test, fragment: }
{scheme: , host: , path: file2.test, fragment: }
{scheme: , host: , path: file3.test, fragment: }
```

Another interesting property exposed by the File object is the [`parent`](https://api.dart.dev/dart-io/FileSystemEntity/parent.html) one (usually a directory).

```dart
print(myFile1.parent);
print(myFile2.parent);
print(myFile3.parent);
```

```console
$ dart run
Directory: '.'
Directory: '.'
Directory: '.'
```

Let creates a small closure to summarize and display all those information into a `Map`.

```dart
final fileToMap = (File file) {
  return {
    'absolute': file.absolute,
    'hashCode': file.hashCode,
    'isAbsolute': file.isAbsolute,
    'parent': file.parent,
    'path': file.path,
    'runtimeType': file.runtimeType,
    'uri': toMap(file.uri),
  };
};

print(fileToMap(myFile1));
print(fileToMap(myFile2));
print(fileToMap(myFile3));
```

The next part is to investigate around the methods available. One of the most important is probably the [`exists()`](https://api.dart.dev/dart-io/FileSystemEntity/exists.html) method, which returns if a file exist or not. Another one called `existsSync()` is also available, and will return a boolean instead of a `Future` because of its synchronous nature. In fact, most of the following methods will also have their synchronous function if needed. Let creates two of those files first, `file1.test` and `file2.test`.


The previous command is maybe a bit hard to understand for someone without Perl experience. In short, we are filtering the output from `/dev/random` to extract only characters matching the alphabets or numbers. ```

Now few files have been created, one using binaries and another one using text-like random data, it will be interesting to check the next methods. Let check the [`length()`](https://api.dart.dev/dart-io/FileSystemEntity/length.html) method, it should return the size of a file.

```dart
final fileSize = (File file) async {
  try {
    final size = await file.length();
    print("$file.path: $size");
  }
  catch (e) {
    print("$file.path: $e");
  }
};
fileSize(myFile1);
fileSize(myFile2);
fileSize(myFile3);
```

```console
$ dart run
File: './file1.test'.path: 8192
File: './file2.test'.path: 1122
File: 'file3.test'.path: PathNotFoundException: Cannot retrieve length of file, path = 'file3.test' (OS Error: No such file or directory, errno = 2)
```

When a file does not exist, the function throw a [`PathNotFoundException`](https://api.dart.dev/dart-io/PathNotFoundException-class.html) exception. Then, it's important to check the existence of the file before executing these methods. Let do the same test with the [`stat()`](https://api.dart.dev/dart-io/FileSystemEntity/stat.html) method. It should return a [`FileStat`](https://api.dart.dev/dart-io/FileStat-class.html) object.

```dart
final fileStat = (File file) async {
  try {
    final stat = await file.stat();
    print({
      'accessed': stat.accessed,
      'changed': stat.changed,
      'mode': stat.mode,
      'modified': stat.modified,
      'size': stat.size,
      'type': stat.type,
    });
  }
  catch (e) {
    print("$file.path: $e");
  }
};
fileStat(myFile1);
fileStat(myFile2);
fileStat(myFile3);
```


Interesting. When executing the `stat()` method, no exceptions are thrown. I would expect the same behavior than the `length()` method, but it seems it's not the case. More investigation is required to know why it does that, but the object returned got a `notFound` type. My guess is, if you are lazy to check for the exceptions, using the `stat()` looks to be the right way. Our `file3.test` still does not exist, let create it using the [`create()`](https://api.dart.dev/dart-io/FileSystemEntity/create.html) method and check what will happen for the 2 others files already created.

```dart
final fileCreate = (File file) async {
  try {
    final created = await file.create();
    print(created);
  }
  catch (e) {
    print("$file.path: $e");
  }
};

fileCreate(myFile1);
fileCreate(myFile2);
fileCreate(myFile3);
```

```console
$ dart run

File: './file2.test'

```

When a file is already present on the file system, calling the `create()` does nothing apparently. Now all these files are created and contains some data (or not), it's the moment to [`open()`](https://api.dart.dev/dart-io/FileSystemEntity/open.html) them. 

```dart
print(await myFile1.open());
print(await myFile2.open());
print(await myFile3.open());
```

```console
$ dart run
Instance of '_RandomAccessFile'
Instance of '_RandomAccessFile'
Instance of '_RandomAccessFile'
```

It returns a [`RandomAccessFile`](https://api.dart.dev/dart-io/RandomAccessFile-class.html) object, we will talk about it later, but with this object, a file can be closed via the [`close()`](https://api.dart.dev/dart-io/RandomAccessFile/close.html). A good practice is to always ensure an opened file is closed in some way when it is not used anymore to avoid [file descriptor exhaustion](https://medium.com/@badrikmodi/the-silent-killer-file-descriptor-exhaustion-in-modern-services-9144bf795b6f). Anyway, this returned object is important if you have operations to execute in a long living process. How to deal with this object will be the topic of another article. For now, reading or writing data in one single step will be enough.

The [`readAsBytes()`](https://api.dart.dev/dart-io/FileSystemEntity/readAsBytes.html), [`readAsLines(https://api.dart.dev/dart-io/FileSystemEntity/readAsLines.html)`]() and [`readAsString()`](https://api.dart.dev/dart-io/FileSystemEntity/readAsString.html) have been created for this purpose, read a whole file, return its content and automatically close it. 

The `readAsBytes()` method returns a `List<Uint8>`, perfect to deal with `myFile1` containing binary data. The `readAsString()` method returns a `String`, perfect to read the content of `myFile2` containing alphanumerical characters. The `readAsLines()` method can also be used, it will return a `List<String>`, each lines being separated by `\n`.

```dart
print("myFile1:");
print((await myFile1.readAsBytes()).take(10));
print("myFile2:");
print((await myFile2.readAsString()).substring(0,10));
print("myFile2:");
print((await myFile2.readAsLines()).take(2));
```

The same methods exist to write data to a file, with the [`writeAsBytes()`](https://api.dart.dev/dart-io/FileSystemEntity/writeAsBytes.html) and [`writeAsString()`](https://api.dart.dev/dart-io/FileSystemEntity/writeAsString.html) ones. To avoid overwriting the data present in `myFile1` and `myFile2`, some data will be added to `myFile3`, the only empty file.

```dart
await myFile3.writeAsBytes(ascii.encode("new data added"));
print(await myFile3.readAsString());

await myFile3.writeAsBytes([0x41, 0x42, 0x43]);
print(await myFile3.readAsString());

await myFile3.writeAsString("this is a string");
print(await myFile3.readAsString());
```

```console
$ dart run
new data added
ABC
this is a string
```

When a file is not needed anymore, it is also possible to remove it from the filesystem with the [`delete()`](https://api.dart.dev/dart-io/FileSystemEntity/delete.html) method. It will return a [`FileSystemEntity`](https://api.dart.dev/dart-io/FileSystemEntity-class.html) object (a superclass of `File`). If the File object to remove is a directory, the [`recursive`](https://api.dart.dev/dart-io/File/delete.html) parameter can be set to remove all files recursively present in it.

```dart
print(await myFile1Rename.delete());
print(await myFile2Rename.delete());
print(await myFile3Rename.delete());
```

Finally, the last method to see is the [`watch()`](https://api.dart.dev/dart-io/FileSystemEntity/watch.html) method. This one is probably one of the most interesting to investigate. The idea is to subscribe to the filesystem to follow the activity on a file, when a change happens, the `Stream` object receives an event from it . On Linux, it uses the [`inotify` API interface](https://manpages.debian.org/trixie/manpages/inotify.7.en.html).

```dart
final timeout = () {
  Duration delay = Duration(seconds: 10);
  final action = () => exit(1);
  Future.delayed(delay, action);
};
timeout();

File toWatch = File("./watcher");
toWatch.create();
Stream watcher = await toWatch.watch();
watcher.listen((event) {
  print(event);
});
```

The code below is a bit more complex than usual. A `timeout` closure is defined, it will stop the application after 10 seconds by calling the `exit()` function. When watching a file in the main thread, the program will simply wait for event forever, the `timeout` closure has been created to avoid being stuck in this loop.

Then, the `./watcher` file is created, and the `watcher` `Stream` is attached to it. Because it's a standard Stream, one can `listen()` on event on it and do some actions.

It's now possible to modify the file from another shell to see the changes happening while the application is running.

```console
$ echo test > watch.test

$ echo test > watch.test

$ echo test > watch.test

$ rm watcher
```

```console
$ dart run

```

The `FileSystemEvent` object returned identify the event applied to the file. It can be set to [`create`](https://api.dart.dev/dart-io/FileSystemEvent/create-constant.html), [`delete`](https://api.dart.dev/dart-io/FileSystemEvent/delete-constant.html), [`modify`](https://api.dart.dev/dart-io/FileSystemEvent/modify-constant.html) or [`move`](https://api.dart.dev/dart-io/FileSystemEvent/move-constant.html). Few of them will be only displayed when following the activity on a directory. For example, removing a file while watching it, and then recreate it will not work, but this action can be seen when watching a directory.
